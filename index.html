The central argument

AI did not make the foundations obsolete. It changed what graduates need to do with them.

R22 already carries substantial mathematics, programming, algorithms, databases, operating systems, AI, machine learning, NLP and deep learning.

The real gap sits in the layer between a model and a dependable product: retrieval, evaluation, deployment, observability, reliability, security and AI-assisted engineering. That is what this redesign spends its 32 credits on — not more subjects, but a reallocation.

03 · Subject categorisation

What stays, what changes?

Every label below is grounded in a specific tool, textbook edition, or course unit — filter to inspect.

Keep

Data Structures

BSTs, AVL/Red-Black trees, heaps and hashing (Gilberg & Forouzan, Data Structures: A Pseudocode Approach with C, 2nd ed.) stay untouched — reasoning about structure survives AI code-generation, and interview loops still test it directly.

Keep

Operating Systems

Processes, memory, concurrency and scheduling underpin every container and inference server a graduate will touch; no reduction proposed.

Keep

DBMS

ER modelling, SQL (UNIT-III), normalisation and transactions (Silberschatz/Korth, Database System Concepts) — RAG pipelines and feature stores still sit on relational and vector storage that behaves by these same rules.

Keep

Machine Learning

Statistical learning theory is unchanged; assessment shifts toward evaluation and failure analysis rather than more algorithm derivations (see Update below).

Keep

Mathematical & Statistical Foundations

Linear algebra and probability were independently named as the most durable college learning by our practitioner interview — no change.

Update

Software Engineering

Pressman's process models (UNIT-I) stay; add AI-assisted development, code review and output verification as a graded practicum component — directly requested by our interviewee ("Git/GitHub collaboration... deployment").

Update

Natural Language Processing

Classical NLP stays as foundation; extend with retrieval-augmented generation, tool use and evaluation of generated text, matching the R25 addition of a dedicated Prompt Engineering skill course.

Update

Deep Learning

Keep backprop and CNN/RNN fundamentals; add inference efficiency, quantisation and smaller-model literacy — the Stanford AI Index and Epoch AI both track capable small models as a 2025–26 trend.

Update

Computer Networks

Trim legacy protocol depth by one credit; keep the freed time inside the course for API/service-to-service traffic patterns that AI microservices actually generate.

Reduce

Automata Theory & Compiler Design

Our interviewee named ATCD first when asked what to cut. Keep formal-language concepts (regular/context-free grammars, why parsers matter) as a 1-credit theory module; drop the full compiler-construction lab track.

Reduce

Nature Inspired Computing

Genetic algorithms and swarm optimisation get a lecture inside Deep Learning instead of a dedicated 3-credit elective slot.

Reduce

DevOps

R25's own Constituent-Colleges syllabus already makes this call: DevOps drops from a 3-credit Professional Core (as it still is in the Affiliated-Colleges R25 document) to a 1-credit Skill Development lab. We agree with the Constituent version and adopt it — see the R25 Reality Check section.

Reduce

Knowledge Representation & Reasoning

Folded into a new AI Systems & Agents course rather than standing alone — symbolic reasoning is now one ingredient in agent design, not a separate unit.

Add

Generative AI, LLMs & RAG

Mandatory core course + lab. R25 already makes Generative AI a core IV-I subject for both AI&ML tracks — we go further and add RAG-system design and evaluation, which R25 does not name explicitly.

Add

Agentic AI Systems & Orchestration

Multi-step tool-using AI systems are named directly by our interviewee ("AI-agent systems and AI system architecture") and by R25, which lists Agentic AI as a III-I Professional Elective — we make it a mandatory IV-II core instead of an elective.

Add

Applied MLOps & Model Deployment

Docker, Kubernetes, model monitoring and CI/CD for ML — the single largest gap named in our interview ("production-level MLOps... keep those models running reliably").

Add

LLM & AI Security

Prompt injection, sensitive-data leakage and unsafe outputs (OWASP Top 10 for LLM Applications, 2025) — a genuinely new risk category that didn't exist when R22 was written.

04 · The 2026 reality

AI work has changed shape

Eight verifiable shifts since R22 was written, each mapped to an affected course.

Generative AI is mainstream

Organisational AI adoption expanded rapidly through 2025–26, making foundation-model literacy a baseline expectation rather than an elective topic. Impacts: AM603PC (NLP), AM701PC (Deep Learning), new GenAI core

Inference got cheaper

Falling per-token inference cost makes it economical to embed models inside ordinary CRUD products, not just AI-labelled ones. Impacts: CS304PC (Software Engineering), CS403PC (DBMS)

Agents are emerging

AI systems increasingly plan, call tools, and hold memory across steps rather than answer once. Impacts: AM601PC (KRR) → new Agentic AI core

Evaluation matters more

Static benchmarks saturate or fail to capture real-world reliability, so evaluation methodology is now its own skill. Impacts: AM502PC (Machine Learning), AM701PC (Deep Learning)

AI-written code needs verification

Widespread use of AI coding assistants means the fresher skill is reviewing and debugging generated code, not typing it from scratch. Impacts: CS304PC (Software Engineering), AM501PC (DAA)

LLM security is a new category

Prompt injection and data disclosure via LLMs are attack classes that postdate R22's AI/Networks content entirely. Impacts: CS404PC (Intro to AI), AM503PC (Computer Networks)

MLOps is becoming LLMOps

Production AI now needs pipelines, versioning, monitoring and rollback for prompts and retrieval indexes, not just model weights. Impacts: AM606PC (Mini Project/Internship/SDC-DevOps), new MLOps core

Smaller models are improving fast

Capability once exclusive to frontier-scale models is increasingly available from small, cheaply-hosted ones, changing infrastructure assumptions for student projects and start-ups alike. Impacts: AM701PC (Deep Learning)

Evidence base

Stanford AI Index 2026 — Economy Stanford AI Index 2026 — Technical Performance Stack Overflow Developer Survey 2025 — AI OWASP Top 10 for LLM Applications, 2025 CNCF 2025 Cloud Native Survey — Kubernetes for AI
05 · The R25 test

JNTUH already moved. Did it move the right amount?

JNTUH released R25 (AY 2025–26 onward) while this audit was underway. Two versions of the CSE (AI&ML) syllabus exist — Affiliated Colleges and University Constituent Colleges — and they disagree with each other on DevOps.

The trap we almost fell into

An early search returned the Affiliated Colleges R25 CSE document, where DevOps (course code CS503PC) is a 3-credit Professional Core subject. A second, separate PDF — the University Constituent Engineering Colleges R25 CSE (AI&ML) syllabus — reduces DevOps to a 1-credit Skill Development Course lab inside III Year II Semester. Citing the wrong one would have silently flipped our biggest finding. We verified both PDFs directly against JNTUH and JNTUH college mirrors before writing the row below. One more layer worth stating plainly: our own R22 baseline doesn't have a standalone DevOps course either — it's bundled into AM606PC, a 2-credit "Mini Project/Internship/Skill Development Course (DevOps)" slot (confirmed against the official R22 PDF). So the real before/after for our branch is 2 → 1, not 3 → 1; the 3-credit figure belongs to general CSE, not CSE(AI&ML).

Direct answer to the assignment's R25 prompt

We agree with the direction of reducing DevOps (Constituent Colleges model) — a single tools-focused slot is better taught distributed across a proper MLOps core; for our own branch that's a 2 → 1 credit move, not 3 → 1 (see the note above). One 20-Minute Conversation

Who: Recent JNTU Sultanpur CSE (AI&ML) graduate, now working as an AI/Software Engineer.

Biggest gap named: production-level MLOps and system design — college teaches model-building on clean datasets; industry adds messy data, pipelines, deployment, monitoring, Docker and Kubernetes.

Most useful college subjects: Linear Algebra, Probability & Statistics, DSA, Design & Analysis of Algorithms.

Least useful in current role: Compiler Design/ATCD — not for removal outright, but for reduced depth and assessment weight.

Unexpected insight: implementing ML algorithms from scratch — which felt like the "serious" academic skill in college — has very little day-to-day value in industry. What matters is knowing when to use a method, verifying its output, debugging failures, and integrating it into a larger system.

09 · Reality check & falsification

What would prove this wrong?

What would disprove this proposal

If placement data over the next two admission cycles showed R22-degree graduates matching R25/2030-style graduates on production-deployment interview rounds at the same rate — i.e., if the MLOps/GenAI gap named by our interviewee turned out not to show up in actual hiring outcomes — that would undercut the case for reallocating credits toward it.

An assumption we changed our mind about

We initially assumed the curriculum's biggest problem was "not enough AI" and planned to simply add Generative AI and Agentic AI courses on top. The interview reframed this: R22 already has a lot of AI content. The real problem is the missing middle layer between a trained model and a dependable product — which argued for reallocation (cutting ATCD, KRR, Nature-Inspired Computing, and a reduced DevOps) rather than pure addition.

Documents we could not access

We could not obtain a JNTU Sultanpur college-specific syllabus variant (if one exists separately from the university-wide R22 PDF), and we did not access internal placement-cell data on where R22 graduates actually get rejected in interviews — both would sharpen the industry-match section beyond the three public job postings used here.

An AI claim we verified independently

Early in this research, a general-knowledge answer about "the R25 DevOps credit change" could easily have been sourced from whichever R25 PDF a search happened to surface first — and the Affiliated-Colleges and University-Constituent-Colleges versions disagree (3 credits vs. 1 credit). We fetched both PDFs directly and cross-checked the course code (CS503PC) and credit line before writing the R25 section, rather than trusting a single search snippet.
